# Clips Camera - Plan

## Goal

A native iPhone app (Andrew's iPhone 17 Pro only) that films an at-bat at 1080p/240fps, lets Andrew tap the screen as each pitch reaches the plate and label it, builds the finished "quick version" on the phone, and uploads only that finished video to Baseball Clips. The phone's edit is final; the raw recording is deleted after the upload succeeds.

Decisions behind this plan were made in the 2026-10-11 Q&A (see memory `clips-camera-app`). Don't re-litigate them.

## Product contract

**Setup (once per game)**
- R1. Pick the kid (Clips' existing kid list) and the game (recent Clips games for that kid, or type a new name; date defaults to today). Sticky until changed.

**Recording**
- R2. Phone held horizontally; full-screen preview; controls live in the side bars. Back camera, 1920×1080 at 240fps, with sound.
- R3. Tap anywhere on the preview = a pitch at that instant (the moment the ball reaches the plate). No latency compensation.
- R4. Each tap opens a label popover over the preview while recording continues: Ball · Called strike · Swinging strike · Foul · In play · Hit by pitch. In play → Grounder · Line drive · Fly ball · Pop-up · Bunt → Single · Double · Triple · Home run · Out · Error · Fielder's choice.
- R5. A tap on the preview while the popover is open dismisses it and logs a new pitch; the earlier pitch stays unlabeled and can be labeled from the pitch strip.
- R6. The count is shown live and tracked scorebook-style (two-strike fouls don't add a strike). Walk, strikeout (looking/swinging) and HBP end the at-bat automatically; in play ends it once a result is chosen.
- R7. "Undo last pitch" is always visible while recording.
- R8. When the at-bat ends, a "Stopping in 3…" countdown with Keep Recording runs; recording stops no earlier than 3s after the final pitch. Manual Stop always works; an at-bat stopped without a result is saved as unfinished (result blank).

**The edit**
- R9. Per pitch: 2s before the tap → 1s after at real speed (3s after on contact). Swings (swinging strike, foul, in play) get an instant replay of 0.8s before → 0.4s after at ¼ speed, muted. Overlapping windows are clipped so nothing plays twice at real speed — the same rules as the web quick version.
- R10. Burned-in caption per pitch ("Pitch 3 · 1-2 · Foul") and a closing card with the result ("Single · Line drive").
- R11. Output is 1920×1080 at 60fps, so a ¼-speed replay keeps every captured frame. H.264 for universal playback (coach, browsers), short keyframe interval so Clips can frame-step and scrub instantly.
- R12. Timings are settings in the app; changes apply to future at-bats only.

**Upload & Clips**
- R13. After stopping, the edit builds and uploads in the background; the camera is ready for the next at-bat immediately. Uploads use cellular, survive the app being closed, and queue when offline.
- R14. The raw recording is deleted once its edit has uploaded. A queue screen shows each at-bat's state (building / waiting for signal / uploading / done / failed + retry).
- R15. In Clips, a phone at-bat appears in the same feed and game pages, with the result on its card and a contact-frame poster. Its player plays the file as-is, with prev/next pitch working; marker editing, Detect, replay zoom and the quick/full switch are hidden. Export shares the file directly (no render). A game reel includes phone at-bats whole.
- R16. One-time Google sign-in (same account as Family HQ), then stays signed in.

**Out of scope (v1):** Scorelord sync, practice/lesson mode, editing a phone at-bat after upload, any device other than the 17 Pro.

## Key technical decisions

- **Location & project:** `ios/ClipsCamera/` in this repo, SwiftUI, Swift 6, iOS 26 minimum, landscape-only. Project generated by XcodeGen (`project.yml`) so the project file stays reviewable; generated `.xcodeproj` is gitignored. Bundle id `io.mason.clipscamera`, team `S4AV4J8F99`.
- **Capture:** `AVCaptureSession` + `AVCaptureVideoDataOutput`/`AVCaptureAudioDataOutput` → `AVAssetWriter` (HEVC raw recording), not `AVCaptureMovieFileOutput`, so tap times map exactly onto video timestamps via the session's synchronization clock. Format chosen by scanning for 1920×1080 with a ≥240fps range; frame duration locked to 1/240.
- **Tap timing:** a tap records the synchronization-clock time; pitch `t` = tap time − first video frame time. Stored to the millisecond.
- **Edit:** `AVMutableComposition` with `scaleTimeRange` for replays; captions and the end card drawn by a custom Core Image compositor; rendered with `AVAssetReader` → `AVAssetWriter` (H.264, ~12 Mbps, keyframe every 0.5s, 60fps). The segment logic is a Swift port of the web `buildQuickPlan`, kept rule-for-rule identical and unit-tested against the same cases.
- **Upload:** supabase-swift for auth and table writes (RLS is family-wide, already allows signed-in members). File upload = signed upload URL + background `URLSession` upload task (re-requests the URL if it expired while offline). No TUS needed at ~30–60 MB. Upload order: poster → video → rows marked ready, so Clips never shows a half-uploaded at-bat.
- **Pitch `t` for phone at-bats** is the pitch moment in the edited video's timeline (start of the pitch's real-speed window + 2s), so the web player's prev/next and markers work without knowing about the raw recording.
- **No worker involvement:** the phone produces the playback-ready file and the poster itself; the at-bat is inserted as `ready` with `playback_path` set.
- **Thermal/battery:** show thermal state; warn at "serious". Stop the capture session entirely between at-bats when idle > 60s (preview resumes on tap).
- **Local persistence:** a small JSON queue in the app's Application Support directory (at-bat id, game, pitches, file paths, state). Raw file deleted after upload confirms.

## Schema (migration `00199`; prod is at `00198` as of 2026-10-11 — re-check before shipping)

- `clip_at_bats.source text not null default 'upload' check (source in ('upload','camera'))`.
- `clip_at_bats.result` check gains `'PO'` (popout) and `'FC'` (fielder's choice). Mapping from the popover: Out + grounder/bunt → GO, fly → FO, line → LO, pop-up → PO; Error → ROE; FC → FC.
- `clip_pitches.outcome` check gains `'hit_by_pitch'`.
- `clip_pitches.batted_ball text check (batted_ball in ('ground_ball','line_drive','fly_ball','pop_fly','bunt'))` — Scorelord's names, for a future sync.
- `clip_pitches.source` check gains `'camera'`.

## Web changes (Clips)

- Types/queries: carry `source`, `batted_ball`, new result and outcome values (labels, captions, scorebook count — HBP ends the count).
- Player: `source = 'camera'` → plain playback of the file, pitch jumps from `t`, edit/Detect/zoom/quick-full controls hidden; Export = share/download the file.
- Game reel export: a camera at-bat contributes one full-length real-speed segment.
- At-bat card: no "needs marking" state for camera at-bats.

## Phases

**Phase 1 — Capture spike (on-phone only, no Clips).** Recording at 240fps, tap + popover + count + undo + auto-stop, edit build, save the edit to Photos. Installed over a cable. Exit criteria: a full simulated game (8+ at-bats over ~2 hours) without overheating or excessive battery drain; edit builds in < 20s per at-bat; replays visibly smooth; captions correct.

**Phase 2 — Clips integration.** Migration 00199, web changes, Google sign-in, game/kid picker, background upload queue, raw deletion. Exit: an at-bat recorded in the backyard appears in the Clips feed, plays, prev/next works, coach export shares the file.

**Phase 3 — TestFlight + first real game.** Archive and upload builds from the command line with an App Store Connect API key. Exit: one real game filmed end-to-end.

## One-time steps for Andrew (click-by-click instructions delivered when each phase starts)

- Phase 1: turn on Developer Mode on the phone and trust the Mac (cable install).
- Phase 2: add the app's sign-in return address to Supabase's allowed redirect URLs (dashboard).
- Phase 3: create the app record in App Store Connect and an App Store Connect API key for automated uploads; install TestFlight on the phone.

## Risks

- **Sustained 240fps heat:** the 17 Pro's vapor chamber should cope in shade; direct summer sun is the unknown. Phase 1 measures it.
- **Low light:** 240fps caps exposure at 1/240s; evening games under poor lights will be noisy/dark. Mitigation if needed: a 120fps setting.
- **Popover while watching the field:** labeling needs a glance at the screen between pitches. Big targets, thumb-reachable in the side bars; validate in Phase 1.
- **Edit on the phone is final:** a bad tap that wasn't undone ships. Accepted by Andrew.
